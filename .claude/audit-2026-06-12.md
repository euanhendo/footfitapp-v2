# Walkthrough audit — 2026-06-12

Raw screen-by-screen feedback from the user's phone walkthrough, triaged.
Working order: change → /verify → device check. Living doc — more feedback expected.

## P1 — Credibility & correctness (no new assets needed)

1. **Score breakdown speaks human** (Result). Today: "your length 269, boot 240–299" —
   meaningless range (reads like the whole size run, not the recommended size).
   Wanted: the recommended size's max length, spare room translated into toe-room
   language (e.g. "~half a size of room"), width version too: where you sit vs the
   boot's max width, plus comfort guidance ("snug — will stretch over time, may be
   uncomfortable at first").
2. **Show estimated foot measurements for basic inputs** (Result/profile card).
   User entered UK 8.5 + wide and got nothing back. Wanted: the mm range the app
   already derives internally (e.g. wide ≈ 110–102, standard ≈ 102–95 — use the real
   numbers from `lib/fitting.ts`, not these guesses). Pair with a persistent-but-polite
   scanner nudge: "scan with your phone for more accurate results."
   Builds on `measureSource` provenance (a3b0c16).
3. **Buy link goes to the retailer, not Google** (Result → boot). Clicking Puma Future
   Ultimate opened a Google page. Store a direct product/retailer URL per boot in
   `bootDatabase.json`. (Full multi-retailer price comparison: see Deferred.)
4. **Audit sock thickness values** (`sockDatabase.json`). "Make sure the extra mm the
   sock adds is correct" — verify against manufacturer/published data.

## P2 — Flow restructure

5. **ManualInput → step-by-step wizard.** Scan-with-phone promoted as step one;
   if declined → input method choice (shoe size / advanced manual); shoe size →
   size-system picker drops down. Keep fit-feel for the basic path. One question
   at a time, more colour, easier to read.
6. **SockSelection → brand accordion.** Current full list is large/clunky. Brand list
   (column), tap a brand → its socks drop down. Keep the search.
7. **Result filter with fit counts.** Brand filter chips showing how many boots fit:
   "Adidas (3)". Extend `lib/bootListControls.ts`.

## P3 — Visual / asset-dependent

8. **Boot pictures** on each result card; tap → small gallery before the buy link.
9. **Sock pictures** in SockSelection — users recognise socks by sight, not name.
10. **Sport tiles: replace emojis** with live-action imagery (kicking a football,
    runner, rugby tackle). Nike-style, more professional. User may supply
    inspiration screenshots.
11. **Top navigation** (Home button + categories). Part of a bigger home redesign —
    needs design discussion with user screenshots.

## Data expansion

12. **More socks** — as many as possible, the more detail the better. `/add-sock` batches.
